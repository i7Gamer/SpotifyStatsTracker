{# hx-get + hx-trigger replace updateHistoryFilters/updateHistoryTagFilter and the debounce helpers: htmx serializes this form's own inputs, so "which params does a filter change set vs delete" is now just which inputs exist and which are disabled, rather than hand-written URLSearchParams surgery. hx-replace-url is the load-bearing one - see replaceHistoryUrl's note in git history: a filter change must REPLACE the URL, never push, so Back leaves the page instead of walking back through every filter the user tried. tests/test_history_htmx.py pins that it stays replace. hx-sync ...:replace is the AbortController bookkeeping: a newer request aborts the one in flight, so a slow early response can't land on top of a later one. `change` here also fires when the search box blurs after typing, duplicating the debounced `input` request - harmless precisely because of this, and cheaper than the event filter that would suppress it (which needs 'unsafe-eval', see above). `submit` is load-bearing too: it is what makes htmx register a submit listener on this form at all, which is what lets the vendored htmx's shouldCancel suppress the browser's OWN submission. Without it, Enter in #historySearch (the only enabled text field) falls through to a native form submit - a full navigation that PUSHES a history entry and carries an empty query string, desyncing the box from the results after Back. #}
